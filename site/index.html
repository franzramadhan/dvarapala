A guardian at the gate

An anti-DDoS gateway in Rust. It sits in front of your app, limits each client, learns what normal traffic looks like, and drops floods before they reach the upstream. It also runs as a forward proxy for outbound calls, or inside your service through the SDKs.

Get started Configuration View on GitHub

Named after the Dvarapala, the guardian statues at Javanese temple gates. 0.x is alpha: keys and metrics may change between minor versions.

What it protects

Every layer is optional and configurable. Defaults are generic; deployment specifics belong in your config.

RFC 0001

Rate limit per client

Token bucket per client with a bounded table. X-Forwarded-For is trusted only from the proxies you list.

RFC 0002

Adaptive detection

Heavy hitters, a learned rate baseline and source entropy, plus an optional tree model. Start in observe, switch to enforce.

RFC 0003

TLS

rustls listener with ALPN, certificate reload on SIGHUP, bounded handshakes and https:// upstreams.

RFC 0004

HTTP/2 and gRPC

h2c or ALPN to the upstream, trailers passed through, gRPC-shaped local errors, limits against rapid reset and header floods.

RFC 0005

WebSocket

Upgrades are rate limited like any request. Tunnel count, idle and lifetime limits bound what each admitted client holds.

RFC 0009

Connection limits

Open connections per client and in total, an accept rate per client, and header, idle and slow-body timeouts, all before any HTTP is parsed.

RFC 0006

HTTP/3 over QUIC

An optional UDP listener (build feature http3) into the same limits, with Retry under load so spoofed Initials cost no handshakes.

RFC 0007

Forward proxy

Outbound calls to each third-party API held to its agreed rate and concurrency, queued briefly or refused locally before the provider blocks you.

RFC 0008

SDKs

The same rate limit, detection and connection limits in process for Go, Python and JavaScript, over a C ABI, with HTTP middleware.

RFC 0010

Clusters

Replicas behind one load balancer share one per-client limit, one egress budget and one heavy hitter list through Redis or PostgreSQL, synced off the request path.

RFC 0011

XDP fast path

An optional eBPF program on Linux drops blocked sources and SYN or packet floods in the NIC driver. L4 and L7 feed it sources that completed a handshake.

RFC 0012

Challenges and JA4

During an attack, browsers solve a small proof of work instead of sharing the attack limit; a signed cookie keeps them out of it. JA4 fingerprints deny or challenge known bot TLS stacks.

RFC 0013

Per-route policy

Deny scanner paths outright, give a login page its own low rate, limit an API per key or per JA4, and keep machine endpoints out of the challenge. Routes only tighten the global policy.

RFC 0014

Admin API and reload

Block a network for an hour, see the top talkers and the detection state, and change limits, routes or the challenge with SIGHUP: clients keep their buckets, a bad file is refused whole.

RFC 0015

Upstream pools

Spread traffic over several upstreams by round robin or least requests. Health checks and passive ejection take a failing one out; idempotent requests retry on another within a budget.

RFC 0016

Replay

Try a new limit, route or detection threshold on yesterday's access log before it reaches clients: dvarapala replay runs the same layers on a virtual clock and prints the verdict counts.

RFC 0017

WAF

OWASP Coraza with the Core Rule Set, in a coraza-spoa sidecar, inspects what passed the limits and blocks SQL injection, XSS and similar attacks. Start in observe, add exclusions, then enforce.

RFC 0018

Admin console

A web console on the admin listener: live request rates, the detection state, top talkers, blocks and reload. Log in with the admin token or through your OIDC provider.

RFC 0019

Kubernetes operator

Label an Ingress, HTTPRoute or GRPCRoute and a webhook points it at a dvarapala gateway the operator runs for its Service. No change to the app or its manifests; policy edits reload the gateways in place.

RFC 0020

OIDC through Cloudflare Access

Console login trusts the issuer's verified email when it sends no email_verified claim, as Cloudflare Access does. Off by default, and an explicit false still denies.

RFC 0021

Console views

See the running config with secrets redacted, the WAF rules that matched and the agent's rule files, and a health page per layer. Switch detection or the WAF between observe and enforce until the next reload, when admin.mode_switch allows it.

RFC 0022

Traffic history

The overview graph comes back after a reload or in a new tab: the gateway keeps the last 15 minutes in memory. With history.persist, per-minute rows in the PostgreSQL store survive restarts, add up the replicas and go back up to 7 days.

RFC 0023

LLM labels

Turn on sampling from the console for a while: requests that hit a WAF rule, fail a challenge or arrive during an attack go, redacted and off the request path, to an LLM that answers a label such as scanner or credential stuffing. Labels feed logs, metrics and a training file for your own model; they never change a verdict.

RFC 0024

LLM label store

With ml.llm.persist, every replica writes its labels to the PostgreSQL store. The console shows the counts and recent labels of all replicas, they survive restarts, and one export link downloads them as JSON lines for training.

metrics

Prometheus metrics

Verdicts, detection state, challenges, connection limits, tunnels, HTTP/2, QUIC, the store, XDP, the WAF and the LLM labels on a separate listener, so you can watch before you enforce.

How it works

One engine decides a verdict for each request. The proxy only carries it out.

  • Drop packet floods early: an optional XDP program filters in the NIC driver.
  • Bound connections: per-client and total caps, accept rate and timeouts.
  • Identify the client: peer address, or X-Forwarded-For from a trusted proxy.
  • Limit it: a token bucket per client answers 429 when empty.
  • Detect floods: per-window counts against a learned baseline mark anomalies.
  • Challenge browsers with a proof of work during an attack, and fingerprint TLS clients by JA4.
  • Inspect what passed with the OWASP Core Rule Set: an optional Coraza sidecar blocks SQL injection, XSS and similar attacks.
  • Forward what passes to a healthy upstream of the pool, over HTTP/1.1, HTTP/2 or a WebSocket tunnel; clients may also come in over HTTP/3.
  • Share counts across replicas through Redis or PostgreSQL, so a cluster holds one limit.
  • Report every verdict as a metric and a structured log line.

dvarapala.toml

# the smallest useful config
listen = "0.0.0.0:8080"
upstream = "http://127.0.0.1:8081"

[rate_limit]
rate = 20     # tokens per second per client
burst = 40

[detection]
mode = "observe"  # log only; "enforce" later

[metrics]
listen = "127.0.0.1:9090"

Install

Binaries for Linux (musl, static) and macOS, x86_64 and aarch64, with SHA256SUMS, and a container image.

Homebrew

brew install franzramadhan/tap/dvarapala

Install script

# checks SHA256SUMS; /usr/local/bin or ~/.local/bin
curl -fsSL https://dvarapala.franzramadhan.dev/install.sh | sh
dvarapala serve --config dvarapala.toml

Cargo

# default features; add --features ml,redis,postgres,http3,xdp
cargo install dvarapala

Latest release

From source

git clone https://github.com/franzramadhan/dvarapala
cd dvarapala
cargo build --release
./target/release/dvarapala serve \
  --config examples/dvarapala.toml

Container

# linux/amd64, linux/arm64; FROM scratch, UID 10001; redis + postgres stores
docker run --rm -p 8080:8080 \
  -e DVARAPALA__UPSTREAM=http://app.example:8081 \
  ghcr.io/franzramadhan/dvarapala:<version>

Environment variables override the file: DVARAPALA__RATE_LIMIT__RATE=5.
