# 0011: XDP fast path for packet floods

| Status | Date | PR | Release |
|---|---|---|---|
| accepted | 2026-10-28 | #72 | unplanned |

> An optional eBPF/XDP program, loaded by dvarapala on Linux, that drops
> blocked sources and per-source packet floods at the NIC driver, before
> the kernel builds a socket buffer, so L4 and L7 only see traffic worth
> their time.

## Problem

Everything dvarapala does today runs in userspace after the kernel has
done its work: the packet is received, a socket buffer is allocated, TCP
or UDP is processed, and the process is woken. That costs roughly 1 to 2
million packets per second per core before any of our limits run.

- **SYN floods:** the kernel's SYN cookies keep the backlog safe, but every
  SYN still costs a softirq and a cookie. RFC 0009 limits only see
  connections that complete.
- **UDP floods:** junk to the QUIC port (RFC 0006) or any UDP port costs a
  receive and a wakeup each. QUIC Retry stops handshake work, not packet
  work.
- **Known bad sources:** a heavy hitter that detection (RFC 0002) drops
  with `403` keeps opening connections that each cost a handshake.

A 10 Gbit/s link carries up to 14.88 Mpps of minimum-size packets. XDP
runs in the driver before any allocation and drops at 10 Mpps or more per
core.

## Proposal

- New optional `xdp` cargo feature (Linux only) and an `[xdp]` section.
  With `xdp.interface` set, dvarapala loads one XDP program on that
  interface at start and detaches it on exit. It needs `CAP_BPF` and
  `CAP_NET_ADMIN` (or root).
- The program only looks at packets to the ports dvarapala listens on
  (TCP `listen`, UDP `quic.listen`); everything else gets `XDP_PASS`
  untouched, so the host's other services are not affected.
- In order, per packet to a protected port:
  1. **Allow list** (`xdp.allow`, LPM trie): pass. Load balancers and
     health checkers go here.
  2. **Block list** (LPM trie): drop. Static entries from `xdp.block`,
     dynamic entries pushed by userspace with a TTL (below).
  3. **Per-source packet rate:** a token bucket per source prefix
     (`prefix_v4`, `prefix_v6`) in an LRU hash; over `pps` with `burst`,
     drop. Separate rates for TCP SYN (`syn_pps`) and UDP (`udp_pps`).
  4. Pass.
- **Dynamic blocks:** in `enforce` mode, prefixes that detection marks as
  heavy hitters and clients refused by the L4 accept rate are pushed into
  the block list for `xdp.block_ttl`. Only sources that completed a TCP
  handshake or a QUIC address validation reach those layers, so a spoofed
  address cannot be used to block someone else.
- **Observe first:** `xdp.mode = "observe"` (default) runs the same checks
  and counts `would_drop`, but passes everything, like detection's
  observe mode.
- **Attach mode:** native driver mode when the driver supports it, else
  generic (skb) mode with a warning; `xdp.attach = "native"` makes a
  driver without support a start-up error.
- A configured `xdp.interface` that cannot be attached is a start-up
  error: an operator who asked for the fast path gets told, not silently
  less protection.
- Kernel SYN cookies stay the defence for the backlog; the program does
  not generate cookies. The docs ask for `net.ipv4.tcp_syncookies = 1`.

### Domain

| Crate / module | Responsibility |
|---|---|
| `crates/xdp-common/src/lib.rs` | `no_std` shared types and the packet parser (Ethernet, VLAN, IPv4, IPv6, TCP, UDP headers, bounds checked), used by the eBPF program and by userspace tests and fuzzing |
| `crates/xdp-ebpf/src/main.rs` | the XDP program (`aya-ebpf`), its own workspace like `fuzz/`: nightly and `bpf-linker` |
| `crates/xdp/src/loader.rs` | load the embedded object, attach, detach on drop (`aya`) |
| `crates/xdp/src/maps.rs` | fill the allow and block tries, expire dynamic blocks, read per-CPU counters |
| `crates/l7/src/rate_limit.rs`, `crates/l4` | report heavy hitters and accept-rate refusals to a block sink |
| `crates/dvarapala/src/config/xdp.rs` | `[xdp]` section |

The compiled program is checked in CI and embedded in the `xdp` crate
with `include_bytes!`, so building the binary does not need nightly or
`bpf-linker`. `aya` is MIT or Apache-2.0 and must pass `cargo deny check`.

### Configuration

| Key | Default | |
|---|---|---|
| `xdp.interface` | unset | Network interface to attach to; unset turns XDP off |
| `xdp.mode` | `"observe"` | `"observe"` counts, `"enforce"` drops |
| `xdp.attach` | `"auto"` | `"auto"` (native, else generic), `"native"` or `"generic"` |
| `xdp.allow` | `[]` | CIDRs never dropped |
| `xdp.block` | `[]` | CIDRs always dropped |
| `xdp.block_ttl` | `"10m"` | How long a dynamic block lasts; `"0s"` turns dynamic blocks off |
| `xdp.max_blocks` | `65536` | Entries in the block trie, static and dynamic |
| `xdp.pps` | `0` (off) | Packets per second per source prefix to protected ports |
| `xdp.syn_pps` | `100` | TCP SYNs per second per source prefix |
| `xdp.udp_pps` | `0` (off) | UDP packets per second per source prefix |
| `xdp.burst` | `200` | Bucket size for the rates above |
| `xdp.prefix_v4` / `xdp.prefix_v6` | `32` / `64` | Source grouping |
| `xdp.max_sources` | `1048576` | Entries in the per-source LRU |

## Implementation notes

Found while building:

- One allow trie and one block trie with IPv4 mapped into IPv6
  (`::ffff:a.b.c.d`), instead of a trie per family. A block's expiry is
  checked in the program too, so an expired entry stops dropping before
  the once-a-second sweep removes it.
- The per-source rates are a GCRA (one arrival time per rate in the LRU
  value) rather than a token count: one subtraction and compare per
  packet, and the same function runs in the unit tests. CPUs racing on
  one source can let a packet or two more through, never fewer.
- Clean passes on a protected port count as `pass{reason="other"}` with
  the packets not to a protected port, so `other` is everything that
  passed without a rule.
- IPv4 fragments after the first, and IPv6 ones, carry no port and are
  "not ours": they pass. Reassembly is the kernel's, as before.
- Heavy hitters reach the block list only when detection is in
  `enforce` mode too, the same rule as RFC 0010 publishing them; an L4
  refusal blocks the client prefix of `[l4]` (`prefix_v4`, `prefix_v6`).
- `crates/xdp` builds everywhere: the config types and the block list
  bookkeeping need no kernel. Its `load` feature (the binary's `xdp`)
  adds `aya` and the loader, Linux only, so a build without XDP links
  no `aya`. The release binary grows by about 390 KB with it.
- The program is built with `debug = false`: no BTF, no host paths, and
  the object is byte for byte the same from a clean target directory.
  `bpf-linker` 0.12 ships prebuilt; its LLVM (23) must match the pinned
  nightly's.
- The kernel tests run as root through a cargo runner (`sudo -E`) when
  `DVARAPALA_TEST_XDP` is set; without it they skip, so the
  unprivileged `cargo test` stays green. Case 12 attaches to `lo` in a
  child process and kills it with `SIGKILL`.

## Alternatives

| Option | Why not |
|---|---|
| nftables / iptables rate limits | run after the socket buffer is built; another tool to configure; no link to detection |
| tc eBPF | later in the stack than XDP, slower; useful only for egress, which we do not need |
| libbpf and a C program | a C toolchain in the build; `aya` keeps it Rust end to end |
| DPDK or AF_XDP in userspace | takes over the NIC, a much bigger operational change |
| Leave it to the cloud or upstream scrubbing | still the answer for floods above the link; XDP covers what reaches the host |

## Security and resource limits

- The attacker controls every byte of every packet. The parser checks
  every access against the packet end, and the kernel verifier refuses a
  program that does not; fuzzing covers the same parser in userspace.
- Spoofed sources fill the per-source LRU: it is bounded by
  `max_sources` and evicts the oldest, so memory is fixed: about 40 MB of
  kernel memory at the default (one shared LRU hash, not per CPU),
  outside the RFC 0001 RSS budget; measured in the implementation PR.
- Dynamic blocks come only from sources that completed a handshake or
  QUIC validation, so spoofing cannot block a victim. They expire, and
  `max_blocks` bounds them.
- A wrong `xdp.block` can cut off real users: `observe` is the default,
  and `allow` always wins.
- Volumetric floods above the link capacity still need the network edge.

## Rollout

- **Rollout:** unplanned. Off at build time (`xdp` feature) and at run
  time (`xdp.interface` unset); `observe` when turned on.
- **Off switch:** unset `xdp.interface` and restart, or `ip link set dev
  <iface> xdp off` detaches it immediately.
