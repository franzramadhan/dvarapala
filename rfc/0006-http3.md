# 0006: HTTP/3 over QUIC

| Status | Date | PR | Release |
|---|---|---|---|
| accepted | 2026-10-27 | #21 | unplanned |

> An optional QUIC listener that serves HTTP/3 into the same L7 layers and
> proxy, with address validation under load so a spoofed UDP flood cannot
> make dvarapala do handshake work.

## Problem

Browsers and mobile clients prefer HTTP/3 when a server advertises it, and
it helps on lossy networks. Dvarapala speaks only TCP.

QUIC moves the attack surface into the gateway's own process. Over UDP the
source address is not verified before the first reply, so:

- A spoofed flood of Initial packets makes the server allocate connection
  state and run handshakes for addresses that will never answer.
- The server's reply to a spoofed Initial can be used for reflection.
  RFC 9000 limits it to 3 times the bytes received until the address is
  validated, but that is still traffic sent to a victim.
- The client key (peer IP) is only trustworthy after address validation.

This RFC depends on RFC 0003 (TLS) and is optional: the TCP listener stays
the primary path.

## Proposal

- Cargo feature `http3` on the `proxy` crate and the binary, off by
  default and marked experimental, because the `h3` crate is pre-1.0 and
  QUIC adds to the binary size (budget: under 2 MB extra, measured in the
  implementation PR).
- `quic.listen` (unset: off) binds a UDP socket, usually the same address
  as `listen`. It reuses the `[tls]` certificate (TLS 1.3 only, ALPN `h3`).
- HTTP/3 requests go through the same tower stack as HTTP/1.1 and HTTP/2:
  rate limit, detection, ML score, proxy. The upstream side uses RFC 0004's
  `upstream_protocol`; there is no HTTP/3 to the upstream.
- The TCP listener adds `Alt-Svc: h3=":<port>"; ma=86400` to responses when
  `quic.listen` is set, so clients discover HTTP/3. `quic.advertise = false`
  turns that off (for testing HTTP/3 with explicit clients only).
- Address validation with QUIC Retry (RFC 9000 section 8.1):
  - `quic.retry = "under_load"` (default): send Retry, which costs no state
    and no crypto, when handshakes in progress exceed
    `quic.retry_threshold` (default `256`). Below it, validate implicitly
    through the handshake.
  - `"always"`: every new connection pays one extra round trip.
  - `"never"`: for lab use only.
  - Retry tokens are bound to the client address and expire after `10s`,
    with a random key per process.
- Limits:
  - `quic.max_connections` (default `10000`): over it, new connections are
    refused with `CONNECTION_REFUSED` before the handshake.
  - `quic.max_streams` (default `100`): bidirectional streams per
    connection.
  - `quic.idle_timeout` (default `30s`).
  - `quic.handshake_timeout` reuses `tls.handshake_timeout`.
- 0-RTT is off: it is replayable and lets a client send data before the
  address is validated.
- The client key is the address the connection was validated from. After a
  migration (a new client address on the same connection) the key moves to
  the new address once QUIC has validated the path.
- Out of scope: WebSocket over HTTP/3 (RFC 9220), WebTransport, HTTP/3
  upstreams, and volumetric UDP floods, which the XDP RFC handles before
  they reach the socket.

### Domain

| Crate / module | Responsibility |
|---|---|
| `crates/proxy/src/quic/endpoint.rs` | `quinn` endpoint, Retry policy, connection limits |
| `crates/proxy/src/quic/h3.rs` | HTTP/3 requests into the tower service, bodies both ways |
| `crates/proxy/src/alt_svc.rs` | `Alt-Svc` on TCP responses |
| `crates/dvarapala/src/config.rs` | `[quic]` section |
| `crates/dvarapala/src/main.rs` | run the TCP and QUIC listeners side by side, shut both down |

### Configuration

| Key | Default | |
|---|---|---|
| `quic.listen` | none | UDP address for HTTP/3; unset turns QUIC off |
| `quic.advertise` | `true` | Send `Alt-Svc` on TCP responses |
| `quic.retry` | `under_load` | `under_load`, `always` or `never` |
| `quic.retry_threshold` | `256` | Handshakes in progress before Retry starts |
| `quic.max_connections` | `10000` | Open connections; over it, refuse before the handshake |
| `quic.max_streams` | `100` | Bidirectional streams per connection |
| `quic.idle_timeout` | `30s` | Close idle connections |

## Alternatives

| Option | Why not |
|---|---|
| `quiche` (Cloudflare) | C++ and BoringSSL in the build; `quinn` is pure Rust and shares rustls with RFC 0003 |
| `s2n-quic` (AWS) | larger dependency tree, its own TLS stack; less shared with the rest |
| HTTP/3 on by default | pre-1.0 crates, extra binary size, and a UDP surface that operators should opt into |
| Always Retry | one extra round trip for every client, also when nothing is wrong |
| Never Retry | spoofed Initials cost handshakes and allow 3x reflection |
| HTTP/3 to the upstream | upstreams are near and on reliable links, where HTTP/3 gains nothing |

## Security and resource limits

- The attacker controls every datagram, including the source address
  before validation. Packets that fail QUIC header or token checks are
  dropped without state.
- Under load, Retry costs one small packet and no state per spoofed
  Initial, and the reply is never larger than the Initial (no
  amplification).
- `max_connections`, `max_streams`, `idle_timeout` and the handshake
  timeout bound memory and time. Worst case memory is about
  `max_connections` times the per-connection state (tens of KB), measured
  in the implementation PR against the RFC 0001 footprint budget.
- 0-RTT is off, so no request is processed before the handshake.
- The client key is only used after address validation.
- Volumetric UDP floods are not this layer's problem: they need XDP or the
  network edge.

## Rollout

- **Rollout:** after RFC 0003 and RFC 0004, not planned for a version yet.
  Off by default at build time and at run time.
- **Off switch:** unset `quic.listen`, or build without `http3`. Clients
  that cached `Alt-Svc` fall back to TCP when UDP stops answering.
