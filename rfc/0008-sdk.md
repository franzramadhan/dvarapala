# 0008: SDKs for Go, Python and JavaScript

| Status | Date | PR | Release |
|---|---|---|---|
| implemented | 2026-10-28 | #43 | v0.5.0 |

> Embed the dvarapala engine in Go, Python and JavaScript/TypeScript
> services: one C ABI over the engine, thin idiomatic packages on top, and
> HTTP middleware for each language's common servers.

## Problem

Some services cannot put a proxy in front of themselves: a serverless
function, a sidecar-free deployment, a team that owns the code but not the
ingress. They still want the same per-client rate limit and flood
detection, with the same keys and the same verdicts as the gateway.

Today the only embedding is the Rust `tower` layer in `crates/l7`. RFC 0001
lists the SDK surface (C ABI for other languages) as a later milestone.
Each team writing its own limiter gets a different algorithm, no detection,
and an unbounded client map that a spoofed-source flood grows without
limit.

## Proposal

- One contract: a C ABI in `crates/ffi` (`cdylib` and `staticlib`) with a
  generated header `dvarapala.h`. Every language package calls it; none
  reimplements the engine.
- The ABI exposes a **guard**: an opaque, thread-safe handle that holds the
  client table, the detector and the trusted proxy list. One call per
  request returns a verdict:

  ```c
  dv_config *cfg = dv_config_new();
  dv_config_set(cfg, "rate_limit.rate", "20");      /* CONFIG.md key names */
  dv_config_set(cfg, "detection.mode", "enforce");
  dv_guard *g = dv_guard_new(cfg);                  /* NULL on error */
  dv_config_free(cfg);

  dv_verdict v;
  dv_check(g, "192.0.2.10", xff_or_null, &v);       /* 0 or an error code */
  /* v.kind: DV_ALLOW, DV_THROTTLE, DV_DROP; v.retry_after_ms */
  dv_guard_free(g);
  ```

- Config goes in as key/value strings with the names in `CONFIG.md`
  (`rate_limit.*`, `detection.*`, `l4.*`, `trusted_proxies`). The ABI stays stable
  when keys are added, errors name the key, and the ffi crate needs no
  TOML or JSON parser. Keys that make no sense in-process (`listen`,
  `[tls]`, `[http2]`, `[upgrade]`, `[forward]`) are an error.
- `dv_check` takes the peer address and the raw `X-Forwarded-For` value;
  the guard applies `trusted_proxies` exactly as the gateway does. The
  clock is internal (monotonic); there is no time argument.
- `dv_stats` fills a struct with counters (requests by verdict, clients,
  evictions, detection state, z-score, entropy). Each package maps them to
  the language's metrics library; the ABI has no Prometheus exporter.
- Errors: every function returns a code, `dv_last_error()` gives a
  thread-local message. Every export runs under `catch_unwind`: a panic
  becomes `DV_E_PANIC`, never an unwind across the boundary. Null pointers
  and invalid UTF-8 are errors, not undefined behavior.
- Packages, each in `sdk/<lang>/`, each a thin layer over the ABI:

  | Language | Binding | Package API | Middleware |
  |---|---|---|---|
  | Go | cgo, static link | `dvarapala.New(Config) (*Guard, error)`, `Check(netip.Addr, xff string) Verdict` | `net/http` (`Guard.Middleware(http.Handler)`) |
  | Python | `ctypes` (stdlib), shared library in the wheel | `Guard(rate=20, ...)`, `check(ip, xff=None) -> Verdict` | ASGI and WSGI |
  | JavaScript / TypeScript | N-API addon (Node, also loaded by Bun and Deno), `.d.ts` types | `new Guard({ rate: 20 })`, `check(ip, xff?)` | `node:http` / Express-style `(req, res, next)` |

  Middleware answers `429` with `Retry-After` (seconds, rounded up, at
  least 1) or `403` with `Connection: close`, the same responses as the
  gateway.
- L4 limits (RFC 0009) are part of the SDK. RFC 0009 is implemented
  first, so the first SDK release has them: RFC 0009 puts the per-client
  connection decision in `engine/src/conns.rs`, and the ABI adds
  `dv_conn_open(guard, ip, &handle)` (0, or `DV_E_LIMIT` with the reason)
  and `dv_conn_close(handle)`, plus the `l4.*` keys for connection caps,
  accept rate, prefixes and `exempt` (the timeouts stay with the host's
  server). Packages wire them where the runtime exposes accepted
  connections:

  | Language | L4 wiring |
  |---|---|
  | Go | `Guard.Listener(net.Listener) net.Listener`: refused connections are closed in `Accept`, `Close` on the conn frees the place |
  | JavaScript / TypeScript | `guard.attach(server)`: the `'connection'` event destroys a refused socket, `'close'` frees the place |
  | Python | `guard.conn_open(ip)` / `conn_close(handle)` for servers with a connection hook; ASGI and WSGI have none, so no automatic wiring, documented |

- Scope of the first release: rate limit, detection, trusted proxies,
  L4 connection limits. Out
  of scope: the tree model (`ml` feature), challenges, a shared state
  store between processes (later, with `crates/store`), WebAssembly
  builds (see Alternatives).

### Domain

| Crate / module | Responsibility |
|---|---|
| `crates/engine/src/guard.rs` | the request decision now in `l7/src/rate_limit.rs` (table, detector, attack limit, verdict), moved here with no behavior change so `l7` and `ffi` share it. Time stays an input |
| `crates/ffi/src/config.rs` | key/value config, validation with the same rules and errors as the binary |
| `crates/ffi/src/guard.rs` | the `dv_*` exports, `catch_unwind`, error codes, thread-local last error |
| `crates/ffi/dvarapala.h` | generated by `cbindgen`, committed; CI fails when stale |
| `crates/node` | N-API addon over the same Rust API (`napi` crate), TypeScript types generated |
| `sdk/go`, `sdk/python`, `sdk/js` | the packages, middleware and their tests |

`l7` keeps its public API; only its internals call `engine::Guard`.

### Configuration

No new keys. The SDKs accept the subset of `CONFIG.md` that applies
in-process, with the same defaults: `trusted_proxies`, `[rate_limit]`,
`[detection]`, and the connection keys of `[l4]` (RFC 0009). Language packages expose them as options named after the
key (`rate`, `burst`, `max_clients`, `detection_mode`, ...).

### Logs and metrics

| | |
|---|---|
| `dv_stats` | counters a package exports as metrics: `requests{verdict}`, `clients`, `evictions`, `detection_state`, `rate_zscore`, `source_entropy` |
| logs | none from the library; packages log through the language's logger at most once per second for throttling and detection transitions |

## Alternatives

| Option | Why not |
|---|---|
| Rewrite the engine in each language | three implementations drift; detection and the bounded table are the hard parts |
| Run the gateway as a sidecar | the case this RFC exists for is when a proxy cannot be added |
| WebAssembly instead of native builds | one artifact everywhere, and it would reach edge runtimes. But the engine takes `std::time::Instant`, which `wasm32-unknown-unknown` cannot create, and per-call host round trips cost more than a native call. A later RFC can add it once the engine takes time as plain ticks |
| PyO3 extension for Python | an extra compiled module per Python version; `ctypes` over the same shared library needs one wheel per platform for every Python 3 |
| `koffi` or another FFI package for Node | a runtime dependency for every user; N-API is built into Node, Bun and Deno |
| A config struct in the ABI | every new key breaks the ABI or needs versioned structs; key/value strings do not |
| gRPC or HTTP decision service | a network hop per request, which is the proxy again |

## Security and resource limits

- The caller is trusted code, but the address and `X-Forwarded-For` values
  come from attackers. The guard parses them with the engine's parser
  (already fuzzed for the gateway), and the ffi entry point gets its own
  fuzz target.
- Memory is bounded the same way as the gateway: `max_clients` entries
  (default 100000, about the same per entry as the gateway's table), least
  recently seen evicted first.
- No unwinding across the ABI, no undefined behavior on null or invalid
  input. The guard is `Send + Sync`; one lock per guard, as in `l7`.
- The packages ship prebuilt libraries: each release adds them to the
  GitHub release with `SHA256SUMS`, built by the same `release.yml` from
  the tagged commit. Registry publishing (PyPI, npm, a Go module tag) is a
  separate decision before the first SDK release.

## Rollout

- **Rollout:** v0.5.0. New crates and packages; the gateway is unchanged apart from
  the `l7` refactor of case 1. Packages carry the workspace version.
- **Off switch:** remove the middleware; the guard keeps no state outside
  the process.

## Implementation notes

- Package config is a map keyed by the `CONFIG.md` names in every language
  (`Config{"rate_limit.rate": "20"}` in Go, `Guard({"rate_limit.rate": 20})`
  in Python, `new Guard({ 'rate_limit.rate': 20 })` in JavaScript), not
  per-key options: `max_clients` exists in both `[rate_limit]` and `[l4]`,
  and a map needs no package change when a key is added.
- `Verdict::Challenge` cannot come out of the guard (no scorer in process);
  the ABI maps it to `DV_THROTTLE` with a 1 s retry should that change.
- Go `Check` takes a `netip.Addr` and returns a `Verdict` with no error: the
  only failure is a zero address, which is dropped (fail closed). The
  middlewares drop a request with no or a bad peer address for the same
  reason.
- Python tests use the stdlib `unittest` (also run by `pytest`), so the CI
  job installs nothing.
- The JavaScript types are the hand-written `sdk/js/index.d.ts` over a
  small wrapper, checked by `tsc --noEmit` on `test/types.ts`; the addon
  (`crates/node`) generates none. The addon calls the `dv_*` functions
  rather than the engine, so its config rules and errors are those of
  `crates/ffi`. `attach` uses `prependListener('connection')`, so a
  refused socket is destroyed before the HTTP server reads from it.
- Libraries are found at `DVARAPALA_LIB` (Python) and `DVARAPALA_NODE`
  (JavaScript), else next to the package; Go links
  `target/release/libdvarapala.a` from the checkout. Releases attach
  `dvarapala-sdk-<tag>-<target>.tar.gz` (static and shared library, the
  Node addon, the header) for glibc Linux and macOS. Registry publishing
  stays a separate decision, as above.
- `dv_check` costs about 200 ns through the ABI (case 14,
  `crates/ffi/benches/check.rs`).
